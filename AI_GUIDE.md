## Development principles
- **Базовые правила:** Соблюдай все общие user rules, они будут предоставлены средой разработки либо отдельным файлом.
- **Инкапсуляция:** При разработке, если появляется логически независимый функционал, который можно вынести в отдельный файл и переиспользовать, то нужно так и сделать.
- **Итеративность:** Всегда разбивать доработку на маленькие кусочки и после каждого кусочка:
  - Прогонять тесты (`npm test`)
  - Проверять консоль браузера/приложения на отсутствие ошибок
  - Убеждаться, что функционал работает корректно
  - Только после этого переходить к следующему кусочку
- **Чистка кода:** После получения одобрения о том, что функционал работает, нужно просмотреть весь код на предмет оптимизации и уменьшения размера кодовой базы:
  - Найти неиспользуемые файлы и удалить их
  - Найти дублирование кода и вынести в переиспользуемые функции
  - Оптимизировать импорты и зависимости
  - Упростить сложные функции
  - Удалить неиспользуемый код

## 📁 Архитектура и Технологии

### Стек
- **Platform**: Electron (Main Process)
- **UI Framework**: React + Vite
- **Language**: TypeScript (Renderer) / JavaScript (Main - legacy parts)
- **Styling**: Tailwind CSS + Shadcn/UI (partial) + Lucide Icons
- **State**: Zustand (Renderer Stores) + Node.js Singletons (Main State)
- **Drag & Drop**: @dnd-kit
- **Testing**: Vitest + React Testing Library

### Поток данных (Data Flow)
1. **Renderer (React)**: Пользователь взаимодействует с UI. Zustand store обновляется оптимистично.
2. **IPC Bridge**: Store вызывает методы через `window.todoApi` / `window.settingsApi`.
3. **Main Process**: `ipcHandlers.js` принимает запрос.
4. **Service Layer**: `todoService.js` выполняет бизнес-логику (валидация, сложные операции).
5. **Persistence**: `todoStore.js.legacy` или `settingsStore.js.legacy` пишут JSON на диск.
6. **Broadcast**: Main process уведомляет все окна об изменениях (`todos-updated`, `settings-updated`).

## 🚀 Реализация Фич и Алгоритмы

### 1. Overlay (Таймер-Индикатор)
*Глобальный визуальный таймер, который "всплывает" поверх всех окон.*

- **Файлы**: `src/overlay/OverlayWindow.tsx`, `src/main/timerManager.js`
- **Механизм окна**: 
  - Создается в `windowManager.js`.
  - Свойства: `transparent: true`, `frame: false`, `alwaysOnTop: true`, `skipTaskbar: true`.
  - `pointer-events: none` (CSS) позволяет кликать сквозь оверлей по элементам других окон.
- **Алгоритм Анимации и Синхронизации**:
  - **CSS**: Анимация перемещения снизу вверх реализована через `@keyframes rise`.
  - **Тайминг**: Длительность `animation-duration` выставляется равной `settings.durationSeconds`.
  - **Синхронизация (Reset Trick)**: 
    - Main process (`timerManager.js`) держит `setInterval`. При завершении цикла он шлет событие `restart-cycle`.
    - React компонент слушает это событие и инкрементирует стейт `key={animationKey}` корневого элемента.
    - Изменение `key` заставляет React удалить элемент из DOM и создать заново — это гарантированно сбрасывает CSS-анимацию на 0%, предотвращая рассинхрон визуала и логики.
- **Режимы отображения (Levels)**:
  - **Level 1 (Basic)**: `div` с `border-radius: 50%` (круг). Цвет зависит от настроек.
  - **Level 2 (Counter)**: Текст с `text-shadow` для читаемости на любом фоне.
  - **Level 3 (Expert)**: Контейнер с `backdrop-blur` (эффект стекла).

### 2. Todo Manager: Иерархия и Рендеринг
*Система бесконечно вложенных задач.*

- **Файлы**: `src/todo/TodoWindow.tsx`, `src/todo/TaskItem.tsx`
- **Структура данных**: Плоский массив объектов `Todo`, где связь задается через поле `parentId` (Adjacency List). Порядок внутри уровня — через поле `order`.
- **Алгоритм Flattening (Дерево -> Список)**:
  - Реализован в `getFlattenedTasks`.
  - Превращает дерево в одномерный массив для рендеринга.
  - **Шаги**:
    1. Найти корневые задачи (`parentId === null`) или детей текущего узла.
    2. Отсортировать по `order`.
    3. Для каждой задачи: добавить в результирующий список -> если `!collapsed`, рекурсивно вызвать функцию для детей -> добавить результат рекурсии следом.
  - Результат содержит поле `depth`, используемое для `padding-left: depth * 24px` в UI.
- **Виртуализация**: Не используется (рендерится весь список), что допустимо до ~200-300 задач.

### 3. Todo Manager: Drag & Drop
*Умное перетаскивание с возможностью вкладывания задач.*

- **Библиотека**: `@dnd-kit`.
- **Алгоритм зон (Smart Zones)**:
  - Реализован в `calculateZone`.
  - Высота целевой задачи (над которой держим мышь) делится на 3 зоны:
    1. **Top 33%**: Перемещение "До" (Sibling Before). Изменяет `order`.
    2. **Center 33%**: Вложение (Make Child). Изменяет `parentId` перетаскиваемой задачи на ID целевой. Целевая задача принудительно раскрывается (`collapsed: false`).
    3. **Bottom 33%**: Перемещение "После" (Sibling After). Изменяет `order`.
- **Логика завершения (onDragEnd)**:
  - При смене родителя пересчитываются индексы (`order`) всех соседей в новой группе, чтобы устранить дыры в нумерации.

### 4. Todo Manager: UI и Редактирование
- **Auto-resize Textarea**:
  - Вместо `contenteditable` используется `<textarea>`.
  - В `TaskItem.tsx` эффект `useEffect` следит за контентом: сбрасывает высоту в `auto`, затем ставит `scrollHeight + 'px'`. Это предотвращает скачки и позволяет полю расти бесконечно.
- **Hotkeys (Локальные)**:
  - Обработчик в `useEffect` окна Todo.
  - `Enter`: Создание задачи того же уровня (Sibling).
  - `Tab`: Превращение текущей задачи в подзадачу предыдущей (Indent).
  - `Delete` (Double confirm): Первое нажатие переводит задачу в режим "ConfirmingDelete" (UI меняется), второе нажатие удаляет. Сброс состояния при смене фокуса.

#### 4.1 Актуальные хоткеи (React-версия)
- **Поведение Enter**:
  - По умолчанию `Enter` внутри `textarea` добавляет **новую строку текста** и не создает новую задачу.
  - Создание задач вынесено в отдельные хоткеи (`Shift+Enter`, `Ctrl+Enter`, `Ctrl+Shift+Enter`).
- **Локальная обработка**:
  - В новой React-версии обработчик хоткеев навешан на корневой контейнер `TodoWindow` через `onKeyDown`, а не на `window`.
  - Событие обрабатывается только если комбинация совпадает с одной из настроек `settings.todoHotkeys`.
  - В полях ввода (textarea/input) обычная печать символов без модификаторов не перехватывается, чтобы не мешать глобальным хоткеям других приложений.
- **Дефолтные хоткеи задач**:
  - Создание задач:
    - `Shift+Enter` — создать задачу того же уровня.
    - `Ctrl+Enter` — создать подзадачу для текущей.
    - `Ctrl+Shift+Enter` — создать корневую задачу.
  - Таймер:
    - `Ctrl+Space` — запустить таймер для текущей задачи.
  - Навигация:
    - `Alt+Down` / `Alt+Up` — переход по плоскому списку.
    - `Alt+Right` / `Alt+Left` — переход к детям / к родителю.
  - Состояние:
    - `Delete` — переключить выполнение задачи.
    - `Ctrl+Delete` — двухшаговое удаление задачи (подтверждение, затем реальное удаление).
  - Backspace:
    - `Backspace` **не удаляет задачи вообще** и лишь блокирует браузерную навигацию "назад" вне полей ввода.

### 5. Settings & Modes
- **Файлы**: `src/settings/SettingsWindow.tsx`, `src/config/modes.js`
- **Пресеты (Modes)**:
  - Хранятся в `modes.js`. Определяют: ID, эмодзи, символ валюты, формулу расчета (например, `$10 * minutes`).
  - Данные режима сериализуются и передаются в рендерер через IPC `get-modes`.
- **Синхронизация**:
  - Выбор папки реализован через `dialog.showOpenDialog` (Main process).
  - Путь сохраняется в `settings.json`.
  - При старте `todoStore` пытается читать файл по этому пути.

- **Хранение и редактирование хоткеев**:
  - В окне настроек есть секция `todoHotkeys` и отдельное поле `resetHotkey` (глобальный хоткей сброса таймера).
  - Хоткеи редактируются через запись комбинации: пользователь нажимает на поле и затем нужную комбинацию клавиш.
  - Ввод нормализуется (например, `ArrowUp` → `Up`, `Ctrl+shift+r` → `Ctrl+Shift+R`), а дубликаты между `todoHotkeys` и `resetHotkey` автоматически очищаются.
  - Все значения сохраняются в `settings.json` и распространяются по окнам через событие `settings-updated`.

### 6. System Integration
- **Трей-иконка (Tray)**:
  - **Файл**: `src/utils/trayIcon.js`.
  - **Алгоритм генерации**:
    1. Проверяет наличие статического файла `assets/tray-icon.png`.
    2. Если нет — генерирует SVG строку (`<circle fill="red" .../>`) на лету.
    3. Конвертирует SVG -> Base64 -> `NativeImage`.
  - Позволяет (в потенциале) менять цвет иконки в зависимости от статуса таймера.
- **Глобальные Хоткеи**:
  - Регистрация в `src/main/timerManager.js` через `globalShortcut`.
  - Дефолт: `Ctrl+Shift+R` (текущее значение берется из `settings.resetHotkey` и может быть изменено пользователем).
  - При срабатывании: сбрасывает таймер, обнуляет счетчики `displayCounters`, отправляет обновленные `settings` во все окна и `restart-cycle` в оверлей, чтобы анимация снова пошла снизу.
- **Прилипание окон (Snapping)**:
  - **Файл**: `src/utils/positioning.js`.
  - При перемещении окна вычисляется расстояние до краев экрана. Если < Threshold (например 20px), координаты принудительно ставятся в 0 или MaxWidth.

### 7. Хранение данных (Persistence)
- **Файлы**: `src/store/*.js.legacy`, `src/services/todoService.js`.
- **Принцип**:
  - Данные хранятся в обычных JSON файлах (`todos.json`, `settings.json`).
  - **Атомарность**: Запись происходит синхронно (в текущей legacy реализации) или через `fs.promises`.
  - **Load Flow**: Main process читает файл -> IPC -> React Store (`useTodoStore.getState().setTodos(...)`).
  - **Save Flow**: React Store (middleware или прямой вызов) -> IPC -> Main process -> запись на диск.
